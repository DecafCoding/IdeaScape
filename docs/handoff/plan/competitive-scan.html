IdeaScape — Competitive Scan

A desktop canvas application. Small ideas (notes, pictures, web links, video) are placed on a canvas and connected together to build a larger concept.

Comparables surveyed: Milanote, Miro, FigJam (Figma), Mural, Obsidian Canvas, Heptabase, Scrintal, Kosmik, tldraw / Excalidraw, Kinopio.
Research prepared: 2026-09-05.
Extended: not yet extended.
Coverage pass: 2026-09-05, against docs/mvp-plan.html. See the footer.

How to read this

Only the Required bucket feeds MVP scope. Those items are table stakes. The application is not what it claims to be without them.

Top 10 and Other are the reviewed backlog. They are recorded here, not decided here. The dev-add-feature skill works through them later, one at a time, against a working application.

Rows badged Never are off the backlog permanently. They are ruled out by the "never" list in docs/mvp-plan.html, section 3.

Market-wide signals

These complaints repeat across every comparable. Each one is a design input for the whole product, not a single feature.

  • Performance at scale. Canvases become slow when they hold many items. Obsidian users report choppy pan and zoom. Scrintal users report slowdown after a few hundred cards.
  • Subscription cost and hard caps. Milanote free stops at 100 items. Miro free stops at 3 editable boards, then jumps to $20 per seat per month. Users say the caps push them to look elsewhere.
  • Data lock-in and weak offline use. Milanote offline support is limited. Milanote has no public API. Users choose Kosmik and Heptabase partly for offline work.
  • Search quality. Milanote search is called practically useless. It returns loose notes instead of the board the user asked for.

Under-met table stakes

Four Required rows are not fully met by the MVP. Each was raised in the interview and accepted on purpose. The stated reason was to prove the rest of the application first.

  • Export. Not in any phase. Every comparable offers some export.
  • Video. Title, thumbnail and a link only. Every comparable plays video in place.
  • Multiple boards. A flat list of canvases. Nested boards are left out.
  • Search. Text over canvas names and card text only. No search inside pictures or linked pages.

Required Table stakes · feeds MVP scope

Pan and zoom canvas In MVP · P1
Every comparable ships this. Milanote uses fixed boards. Miro, FigJam, Mural, tldraw, Kosmik and Kinopio use an infinite canvas.
Sentiment: Users pick infinite canvas tools over Milanote boards when they want freedom. Users also complain loudly when pan and zoom drop frames.
P1 Canvas core. Free placement on a large canvas, with pan and zoom. Smooth movement is a hard gate on the phase.
Text note card In MVP · P1
All ten comparables ship a text card or sticky note.
Sentiment: Milanote users like the writing feel. Some ask for font choice, which Milanote does not offer.
P1 Canvas core. Text notes with basic formatting. Font choice is left out. It sits in the Other bucket.
Image card, by drag, drop and paste In MVP · P3
All ten ship image placement. Milanote, Kosmik and Morpholio push image collection as the main use.
Sentiment: Drag and drop from the desktop is the expected behaviour. Users notice at once when paste does not work.
P3 Rich cards. File drop, file picker and clipboard paste. Files are copied into the project's assets folder.
Web link card with preview In MVP · P3
Milanote, Kosmik, Heptabase and Kinopio fetch a title, an icon and a picture for a pasted address.
Sentiment: The Milanote web clipper scores 4.8 of 5 in the Chrome store. Link capture is the most praised part of the category.
P3 Rich cards. Paste a web address inside the application. The card shows title, icon and preview picture. The browser extension itself is a separate Top 10 row and is not in the MVP.
Video card Partial · P3
Milanote, Miro, FigJam and Kosmik embed YouTube and Vimeo and play in place.
Sentiment: Users expect a video to play in place. They dislike being sent out to another tab.
P3 Rich cards. In: the card shows the video title and thumbnail, and opens the video in the browser on click. YouTube only — Vimeo was removed on 2026-09-06 and a Vimeo address becomes an ordinary link card. Left out: playing inside the card, Vimeo, local video files, and any player controls. This is an accepted gap against a table stake. It was raised in the interview and accepted, to be added after the rest is proved.
Connections between cards In MVP · P2
Milanote draws arrows between items. Obsidian Canvas, Heptabase, Scrintal, Miro and tldraw all draw edges.
Sentiment: Connections are the reason users choose these tools over a folder of pictures. Users ask for labels on the line.
P2 Connections. A line between two cards on one canvas, with arrow direction and an optional text label. Connections join placements, not library items. Curved styling and routing choices are left out.
Move, resize and select cards In MVP · P1
Universal across all ten.
Sentiment: Users judge the whole product on how this feels. Snapping and multi-select are expected.
P1 Canvas core. Drag, resize, multi-select, delete and z-order.
Automatic save and reliable persistence In MVP · P1
Universal. Obsidian and tldraw save to local files. The rest save to a server.
Sentiment: Lost work is the complaint that makes users leave for good.
P1 Canvas core. Every change is written to SQLite. Multi-row changes are written in one transaction, so a crash leaves no half-finished state.
Multiple boards or projects Partial · P4
Milanote nests boards inside boards. Miro and Mural give a flat list of boards. Obsidian gives one canvas file per idea.
Sentiment: Nested boards are a well-liked Milanote idea. Free-plan board caps are a top reason users leave Miro.
P4 Library, widened by P6. In: projects, and a flat list of canvases inside a project, with create, rename, delete and switch. P6 adds Expand Into A Canvas, which is nesting done as a link rather than as a tree: a card points at the canvas that details it, to any depth, and the same card is placed on both canvases. Still left out: a canvas drawn inside another canvas. There are no caps of any kind, because there is no paid tier.
Search across content Partial · P4
All ten offer search. Quality is uneven.
Sentiment: The single loudest Milanote complaint. Search returns loose notes and does not rank the board the user named.
P4 Library. In: text search over canvas names and card text, with canvas names ranked first. That ranking rule is the direct answer to the Milanote complaint. Left out: search inside pictures and inside the content of linked pages.
Undo and redo In MVP · P1
Universal across all ten.
Sentiment: Users treat missing undo on a canvas as a defect, not a missing feature.
P1 Canvas core. A per-session undo and redo stack. It restores deleted items, placements, connections and picture files together. It is cleared when the project is closed. Persistent history sits in Other, as version history.
Export and data portability Not in MVP
Miro and Milanote export to PDF and picture files. Obsidian and tldraw store an open file format on disk.
Sentiment: Lock-in is a market-wide complaint. Users name it as a reason to choose local-first tools.
Not in a phase. This is an accepted gap against a table stake. It was raised in the interview and accepted, to be added after the rest is proved. Part of the same need is already met: each project is a self-contained folder holding a readable SQLite file and the original picture files, on the user's own disk.

Top 10 Ranked backlog · not MVP scope

Ranked by complaint signal first, then by how common the capability is, then by fit to this project. This ranking records the market at research time. It is not re-ranked later.

  1. Smooth performance with many items Partial · P1
    tldraw and Kinopio stay smooth. Obsidian Canvas and Scrintal do not.
    Sentiment: Obsidian forum threads report frame rate drops on pan and zoom. A community patch exists for repeated mounting of embedded media. Scrintal users report slowdown past a few hundred cards.
    Ranked first. It is the loudest repeated complaint in the category. It is also an architecture decision, so it must be answered early or not at all.
    P1 Canvas core. In: culling, so only the cards inside the view window are drawn. A hard gate of 60 frames per second while panning 250 cards. Left out: level-of-detail drawing, worker threads, and any target above 250 cards on one canvas. Events overtook this row's rank. It became a P1 gate rather than a later feature.
  2. Full offline use and local data ownership In MVP · P1
    Obsidian, tldraw, Heptabase and Kosmik work offline. Milanote offline is limited.
    Sentiment: Users name offline work as a reason to leave Milanote. Kosmik markets offline work as its answer to that complaint.
    Ranked second. It is a market-wide signal, not one product's gap.
    P1 Canvas core. The whole application is offline by design. Data lives in a local project folder. Cloud storage of user data is on the "never" list. The only network calls are ones the user starts. Events overtook this row's rank. The storage decision answered it in full.
  3. Browser extension web clipper Not in MVP
    Milanote, Morpholio and Moodboard Grabber ship one. Miro has a light version.
    Sentiment: The most praised single feature found. Milanote's clipper holds 4.8 of 5 in the Chrome store.
    Ranked third. Strong positive signal and a direct fit with collecting ideas from the web.
    Not in a phase. Pasting a web address inside the application covers the same need more cheaply for one user. That is P3.
  4. Real-time shared editing Never
    Miro, FigJam, Mural, Milanote and Scrintal all ship it. Obsidian and tldraw local files do not.
    Sentiment: Teams treat it as required. Single users say they pay for it and never use it.
    Ranked fourth on how common it is. It is a large build and it changes the whole architecture, so it must be a deliberate choice.
    Ruled out. Collaboration is on the "never" list in the MVP plan. IdeaScape is a single-user desktop application. Off the backlog permanently.
  5. No item caps and simple pricing Never
    Milanote free stops at 100 items. Miro free stops at 3 editable boards. Scrintal added a free plan. OmniCanvas markets "no 100-note limit".
    Sentiment: Caps and the jump to $20 per seat are named as the top reason users shop for alternatives.
    Ranked fifth. Loud signal, but it is a business decision more than a build.
    Ruled out as a feature. In-application billing and subscriptions are on the "never" list. The complaint is answered by the product's shape: no accounts, no tiers, no caps. If IdeaScape is ever sold, it is a download with a one-time key checked offline. That is recorded in Other, not here.
  6. Mobile application that can really edit Not in MVP
    Milanote, Miro and Heptabase ship mobile applications.
    Sentiment: Milanote mobile is called a limited companion, with weak canvas viewing and little real editing.
    Ranked sixth. Clear complaint, but a canvas on a small screen is a separate product problem.
    Not in a phase. The MVP targets Windows 11 only. A mobile version would also need a way to move data, which the "never" list keeps off the cloud.
  7. Public API and third-party integrations Not in MVP
    Miro and Figma ship full APIs. Milanote offers no public API and no native integrations.
    Sentiment: Reviewers list the missing API as a specific Milanote weakness.
    Ranked seventh. Real gap, but it matters most to teams and to power users.
    Not in a phase. The deferred export file format would cover part of the same need. Export is itself not in the MVP.
  8. Freehand drawing and ink layer Not in MVP
    tldraw, Excalidraw, FigJam, Miro and OmniCanvas ship it. Milanote does not.
    Sentiment: OmniCanvas markets a real freehand layer as its edge over Milanote.
    Ranked eighth. Common in whiteboard tools, less asked for in idea-collection tools.
    Not in a phase. It would arrive as a new item kind, which the data model supports cheaply.
  9. AI assistance on the canvas Not in MVP
    Miro AI, MockFlow IdeaBoard and Kosmik ship AI features.
    Sentiment: Mixed. Miro AI credits do not roll over, and users must contact sales past the limit. That metering draws complaints.
    Ranked ninth. High interest in the market, but the complaint is about the selling model more than the feature.
    Not in a phase, but the plan already makes room for it. The network rule allows a call the user starts, using the user's own key. That answers the metering complaint by design.
  10. Backlinks and a graph view of connections Not in MVP
    Obsidian, Heptabase and Scrintal connect canvas items to a wider note graph.
    Sentiment: Heptabase scores highest of the group for visual research, which reviewers credit to this linking.
    Ranked tenth. Strong for research users. It is a second product idea on top of the canvas.
    Not in a phase. The MVP data model prepares for it. Items live once in a project library, so relationships between items can be added later without moving the canvas connections, which join placements.

Other Recorded backlog · unranked

Reusable shaped items: characters, tropes, themes In MVP · P6 From interview
Heptabase and Scrintal support typed notes. No comparable ships story-specific item types.
Sentiment: Not found in research. This came from the interview, where the user named characters, tropes and themes as a planned use, with one canvas per chapter.
P6 The writing pack. This row shaped the MVP data model before it was built, and the bet held: a card is a placement pointing at a library item, so one Character appears on many chapter canvases as one record. It cost exactly one new item kind and no rewrite. In: seven typed card types generated from data blueprints, seven field kinds, chips on the card face, connection roles, and a card that expands into its own canvas. See docs/feature-writing-pack.html.
A library screen Partial · P6 From interview
Milanote, Heptabase and Kosmik all show a list of everything in a workspace.
Sentiment: Not found in research. Raised in the interview as the missing piece that makes reusable items usable.
P6 The writing pack. The rule this row predicted has now changed. The MVP deleted an item when its last card was deleted, because an unplaced item could never be seen. That would destroy a reused Character, so P6 exempts blueprint items and ships an Unplaced list in the left column to keep the old rule's promise. The four original card kinds keep the old behaviour exactly. Left out: the full screen showing every item in a project.

Not in a phase. The user stated that any sale would be a download with a one-time key. The key is checked offline. This does not reopen accounts or billing, which stay on the "never" list.
Templates and starter boards Not in MVP
Milanote, Miro, Mural and FigJam ship large template libraries.
Sentiment: Templates are named as a reason new users get started fast. Milanote's steep learning curve is a repeated complaint that templates soften.
Not in a phase. Narrowed and kept on the backlog on 2026-09-07 as book templates: pick a genre and a sub-genre, then fill a Book card's fields from a guide drawn from a previous book. P6 builds the card and field machinery it needs, and its four rulings are already recorded in docs/feature-writing-pack.html §3 and §5, so the later work cannot contradict this one. A general starter-canvas library is not planned.
